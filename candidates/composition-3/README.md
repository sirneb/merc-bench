# QX-16 assemble / execute / decrypt (candidate C3, "composition-3")

Assemble a 58-word program for an invented 16-bit accumulator machine, emulate ~325 instructions of a self-modifying mixing loop bit-exactly, use the resulting 4-word digest to run a 4-lane 16-bit xorshift keystream that decrypts a 74-byte question about the final memory, then answer it.

## What it tests and why

Nothing about the QX-16 can be recalled: its encoding (4-bit opcode / 3-bit mode / 9-bit operand), rotate-through-carry semantics, borrow convention, PC-relative branch bias and indirect-pointer masking are all defined only in the prompt, and one instruction rewrites another instruction's operand at run time, so "reason about what the loop computes" is not a shortcut: the program is a hash whose value can only be obtained by stepping it (or by reproducing its arithmetic exactly at a higher level, which is the same amount of exact work). The four stages probe distinct things:

1. **Spec-following** (Stage 1, 20 pts): two-pass label resolution, forward references, immediates that are label addresses, two relative branches (one forward, one backward) and a self-modified load. Four of the 20 points are reserved for those error-prone words.
2. **Sustained bit-exact state tracking** (Stage 2, 35 pts): ~325 executed instructions with carry chained across `ROL -> ADC` and `ROR -> ... -> ADC`, a data-dependent branch, an indirect table lookup and an indirect write-back that changes the input block. Checkpoints every 50 instructions plus the final state give a graded horizon: the grader reports the first divergent checkpoint, and it re-runs the reference emulator on the model's *own* Stage 1 words so "assembled one word wrong but emulated faithfully" is separated from "assembled right but drifted at step N".
3. **Exact keystream reproduction** (Stage 3, 20 pts): 74 rounds of a fully specified 16-bit shift/xor generator seeded by the digest, scored by character accuracy either against the key or against the decryption implied by the model's own digest, whichever is higher.
4. **Reading the result** (Stage 4, 25 pts): the plaintext is an English question about the final input block; 25 for the true answer, 15 for correctly answering it against the model's own reported memory.

Expected behaviour: low effort produces plausible but invented digest words and garbage plaintext (Stage 1 credit only, ~20-30); higher effort steps further before the first slip, moving the divergent checkpoint later and unlocking conditional credit in Stages 3-4; only a run that is exact through 325 steps can reach 90+. That is a continuous ladder, not pass/fail, and it is where the frontier models should spread out.

Difficulty knobs (`generator.py`): `--difficulty easy|medium|hard|extreme` (input block 5/7/9/14 words, i.e. ~180/250/325/500 executed instructions; extreme also uses two self-modified instructions), `--n-words`, `--self-modifying 0|1|2` (0 replaces the patched load by an indirect pointer), `--interval` (checkpoint density: denser = more partial credit), `--seed`. Shipped: seed 20260926, difficulty `hard`, prompt 13 KB.

## Grading

`python grade.py <run-record.json>` prints `{task, score, total, detail}` with `total = 100`. Ground truth is `key.json`, produced by `generator.py` and independently re-derived from `prompt.txt` alone by `oracle.py` (separate regex-driven assembler, table-driven emulator, generator-based keystream, question parsed from the decrypted text). `python selftest.py` checks: key answer -> 100; ten corruptions (including prose-wrapped/python-repr answers, lowercase/0x hex, and a mis-assembled-but-faithfully-emulated answer) -> the expected stage loses points; oracle == key on 240 generated instances across every difficulty and self-modification setting; and both emulators agree on 300 random instruction images. Hex is normalised (case, `0x`, padding); missing checkpoints score 0 for that checkpoint rather than invalidating the run; a prose answer containing the JSON object is parsed tolerantly. `detail` reports per-stage absolute vs conditional points, the first divergent checkpoint against the key and against the model's own words, and whether the conditional path was used.

Scoring per stage: Stage 1 = 16 x (exact words / 58) + 4 x (exact critical words / 5). Stage 2 = digest 3.75 per exact word (15), instruction count 5 exact / 2 within 5%, final input block 5 proportional, checkpoints 10 split over the 7 checkpoints (each: pc .35, acc .35, c .15, z .15); block + checkpoints take max(absolute, conditional-on-own-words). Stage 3 = 20 x max(char accuracy vs key, char accuracy vs own-digest decryption). Stage 4 = 25 exact, 15 if correct against own data_block, else 0.
